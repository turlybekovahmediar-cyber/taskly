# Taskly

**Биржа задач для малого бизнеса и начинающих специалистов в Казахстане.**
Бизнес описывает задачу через мастер из шести вопросов и получает структурированное ТЗ. Специалисты — студенты и junior — откликаются с ценой и сроком. Оплата резервируется до начала работы и переходит исполнителю только после приёмки результата. Комиссия Taskly — 5% со специалиста, только с успешно завершённых проектов.

🔗 **Рабочая версия:** https://ССЫЛКА-ПОСЛЕ-ДЕПЛОЯ.onrender.com

> Демо-вход без пароля — на странице «Вход» кнопки «Кабинет бизнеса · Barber Loft» и «Кабинет специалиста · Аружан С.». Можно зарегистрировать и свой аккаунт.

## Команда

| Участник | Роль | Зона ответственности |
|---|---|---|
| Имя Фамилия | Backend + БД | схема БД, миграции, API сделки, демо-данные |
| Имя Фамилия | Frontend + интеграция | подключение интерфейса к API, вход и регистрация, деплой |
| Имя Фамилия | Продукт и питч | README, сценарий демо, проверка на живой ссылке, презентация |

## Что умеет продукт

- **Регистрация и вход.** Пароль хранится в виде хеша (bcrypt), сессия — в httpOnly-cookie. Один аккаунт может быть и заказчиком, и специалистом.
- **Бизнес:** создаёт проект через мастер (черновик сохраняется на сервере), смотрит отклики, выбирает исполнителя, резервирует оплату, принимает работу или просит правку, оставляет отзыв. Может пригласить специалиста в проект.
- **Специалист:** ищет проекты по навыкам, откликается, подтверждает приглашения, отмечает этапы, сдаёт результат, получает выплату за вычетом 5%.
- **Общее:** переписка по проекту, изменения задачи (предлагает одна сторона, подтверждает другая), уведомления, отзывы и рейтинг, который считается из реальных данных.

## Архитектура

```
Браузер ──HTTPS──▶  Node.js (Express) — один сервис на Render
                    ├── /api/*  REST API: проверка прав, статусов, лимитов; деньги — в транзакциях
                    └── /*      собранный фронтенд (React + Vite)
                                   │
                                   ▼
                          PostgreSQL (Neon)
```

| Слой | Технологии |
|---|---|
| Фронтенд | React 18, Vite, свой роутер на History API |
| Бэкенд | Node.js 20+, Express, zod (проверка входных данных), helmet, rate-limit |
| База данных | PostgreSQL (Neon), драйвер `pg`, схема в `backend/src/schema.sql` |
| Хостинг | Render (веб-сервис) + Neon (база) |

### Жизненный цикл проекта

```
searching ──select──▶ awaiting_payment ──payment──▶ in_work ──deliver──▶ on_review ──accept──▶ done
                                                                 ▲              │
                                                                 └─ deliver ── needs_fix ◀─ request-fix
```

Сервер проверяет на каждом шаге, **кто** действует (заказчик или исполнитель), **из какого статуса** (иначе `409`) и **лимит правок**. Сумма и комиссия считаются только на сервере.

### Таблицы

`users`, `business_profiles`, `specialist_profiles`, `projects`, `proposals`, `payments`, `messages`, `files`, `change_requests`, `reviews`, `notifications`, `saved_projects`.

## API

Все методы — с префиксом `/api`. Ответ на действие — обновлённые данные для текущего пользователя.

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| GET | `/health` | все | проверка сервера и базы |
| GET | `/state` | все | данные, доступные пользователю (гостю — каталог) |
| POST | `/auth/register` | гость | регистрация `{role, name, email, password}` |
| POST | `/auth/login` | гость | вход `{email, password}` |
| POST | `/auth/demo` | гость | вход в демо-аккаунт `{role}` |
| POST | `/auth/logout` | все | выход |
| PATCH | `/auth/me` | пользователь | переключить кабинет `{role}` |
| PUT | `/me/draft` | пользователь | сохранить черновик проекта |
| PATCH | `/me/business`, `/me/specialist` | пользователь | профиль компании / специалиста |
| PUT, DELETE | `/me/saved/:projectId` | пользователь | сохранённые проекты |
| POST | `/projects` | бизнес | опубликовать проект |
| POST | `/projects/:id/proposals` | специалист | откликнуться |
| POST | `/projects/:id/proposals/read` | владелец | отметить отклики прочитанными |
| POST | `/projects/:id/invite` | владелец | пригласить специалиста |
| POST | `/proposals/:id/withdraw`, `/proposals/:id/confirm` | автор отклика | отозвать / подтвердить приглашение |
| POST | `/projects/:id/select` | владелец | выбрать исполнителя `{proposalId}` |
| POST | `/projects/:id/payment` | владелец | зарезервировать оплату |
| POST | `/projects/:id/stages/complete` | исполнитель | закрыть этап |
| POST | `/projects/:id/deliver` | исполнитель | сдать результат |
| POST | `/projects/:id/request-fix` | владелец | запросить правку |
| POST | `/projects/:id/accept` | владелец | принять работу и выплатить |
| POST | `/projects/:id/reviews` | участник | отзыв о второй стороне |
| POST | `/projects/:id/messages` | участник | сообщение в переписку |
| POST | `/projects/:id/changes` | участник | предложить изменение задачи |
| POST | `/changes/:id/approve`, `/changes/:id/reject` | вторая сторона | решение по изменению |
| POST | `/notifications/:id/read`, `/notifications/read-all` | пользователь | уведомления |
| POST | `/demo/reset` | демо-аккаунт | вернуть демо-данные к исходным |

## Запуск локально

Нужен Node.js 20+ и база PostgreSQL (бесплатно — [neon.tech](https://neon.tech)).

1. Скопировать `backend/.env.example` в `backend/.env` и вписать `DATABASE_URL` и `JWT_SECRET`.
2. На Windows — дважды кликнуть `start.cmd`. Или вручную:
   ```bash
   npm run build
   npm start
   ```
3. Открыть http://localhost:3000. При первом запуске сервер создаст таблицы и загрузит демо-данные.

Для разработки с горячей перезагрузкой — два терминала: `npm run dev:api` (API на :3000) и `npm run dev:web` (сайт на :5173, запросы `/api` проксируются на :3000).

Демо-данные заново: `npm run seed --prefix backend -- --reset` (очищает всю базу).

## Деплой (Render + Neon)

1. Создать базу в Neon и скопировать строку подключения (кнопка **Connect**).
2. В Render: **New → Blueprint** → выбрать этот репозиторий (настройки в `render.yaml`) и вписать `DATABASE_URL`.
3. Render сам соберёт фронтенд, установит зависимости и запустит сервер; таблицы и демо-данные создадутся при первом старте.

Бесплатный сервис Render засыпает после 15 минут без запросов — перед показом откройте ссылку заранее или настройте пинг `/api/health` (например, UptimeRobot раз в 10 минут).
